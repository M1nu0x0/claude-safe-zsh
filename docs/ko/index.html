SafeZsh for Claude

Claude Code Bash 도구에서 no matches found 같은 zsh 오류를 막습니다. Claude는 bash로 쓰고 Bash 도구는 zsh로 실행하는데, 이 플러그인은 zsh가 그 명령을 bash처럼 읽게 합니다.

이 플러그인이 없으면 위 명령은 no matches found: --include=*.ts로 멈추고 grep은 실행되지 않습니다.

설치

Claude Code 터미널 프롬프트에서:

/plugin install safe-zsh --marketplace M1nu0x0/claude-safe-zsh

Add marketplace?에 y를 누르고 scope는 user를 고릅니다.

셸에서는:

claude plugin install safe-zsh --marketplace M1nu0x0/claude-safe-zsh

Claude Desktop에서는 프롬프트 옆 + → Plugins → Add marketplace에 M1nu0x0/claude-safe-zsh를 넣고 safe-zsh를 추가합니다. 다음 세션부터 적용됩니다.

전과 후

만든 이유

macOS는 로그인 셸이 zsh라서 Bash 도구도 zsh로 명령을 실행하지만, Claude는 bash 문법으로 명령을 씁니다.

anthropics/claude-code#103027은 12주 동안 Bash 호출 61,040번 중 2,570번에서 zsh 오류를 셌습니다. 9월 하순부터는 1,000번당 51번이었고, 그중 76%는 명령이 0으로 끝나 오류가 출력 중간에 묻힌 채 Claude가 그대로 읽고 넘어갔습니다.

이 이슈가 Claude Code에서 고쳐지면 이 플러그인은 필요 없어집니다. CI가 매일 이슈 상태를 확인합니다.

동작

세션이 시작될 때(startup, resume, clear, compact) SessionStart 훅이 CLAUDE_ENV_FILE에 한 줄을 덧붙입니다. Claude Code는 이 파일을 Bash 도구 명령마다 앞에 붙이므로, 그 줄이 같은 셸에서 실행됩니다.

if [ -n "${ZSH_VERSION:-}" ]; then setopt no_nomatch sh_word_split no_equals; fi

bash에서는 조건이 거짓이라 0으로 끝나므로, 뒤에 이어진 명령도 그대로 실행됩니다.

막는 것

no_nomatch
--include=*.ts나 ls libs/*/README.md처럼 매치 없는 glob이 명령을 멈추지 않고 그대로 넘어갑니다.
sh_word_split
따옴표 없는 $var가 단어로 나뉘어, for f in $list가 항목마다 한 번씩 돕니다.
no_equals
=로 시작하는 단어를 그대로 둡니다. echo =====가 출력되고, =ls가 /bin/ls로 바뀌지 않습니다.

콜론 modifier($B:path), 첨자로 읽히는 $pat[...], 특수 변수 path와 status, ${!v}나 compgen 같은 bash 전용 문법은 막지 못합니다. 이런 경우는 CLAUDE_CODE_SHELL=/bin/bash로 Bash 도구를 아예 bash로 실행할 수 있습니다.

자주 묻는 질문

내 터미널이나 ~/.zshrc가 바뀌나요?

아니요. 옵션은 Bash 도구의 셸에만 적용됩니다. 터미널, dotfile, 명령 안에서 다시 띄운 zsh -c에는 적용되지 않습니다.

bash를 쓰는데 뭔가 하나요?

아니요. bash에서는 조건이 거짓이라 0으로 끝납니다.

그냥 CLAUDE_CODE_SHELL=/bin/bash를 쓰면 되지 않나요?

그것도 되고 더 많이 해결되지만, Bash 도구에서 내 zsh 함수와 설정을 쓸 수 없게 됩니다. 이 플러그인은 zsh를 그대로 두고 가장 자주 깨지는 세 가지만 끕니다.

어디로 데이터를 보내나요?

보내지 않습니다. 훅은 Claude Code가 준 파일에 한 줄을 덧붙이기만 합니다.

어떤 OS에서 확인했나요?

Ubuntu와 macOS에서 CI가 돌고, 매일 최신 Claude Code로도 확인합니다.

제거하려면 어떻게 하나요?

셸에서 claude plugin uninstall safe-zsh를 실행합니다.

(eval):1: no matches found는 왜 나오나요?

(eval)은 Bash 도구의 zsh가 명령을 eval로 실행하다 난 오류라는 뜻입니다. zsh에서는 맞는 파일이 없는 glob이 오류라서 명령 전체가 거기서 멈추고, bash는 그 단어를 그대로 넘깁니다. 이 플러그인은 zsh도 bash처럼 그대로 넘기게 합니다(no_nomatch). 터미널에서는 같은 오류가 zsh: no matches found로 보입니다.

==== not found는 뭔가요?

zsh는 =로 시작하는 단어를 그 이름의 명령 경로로 바꿉니다(=ls는 /bin/ls). 그래서 echo =====는 ====라는 명령을 찾다가 실패합니다. 구분선으로 =를 늘어놓아 출력하는 명령이 여기에 걸립니다. 이 플러그인은 이 동작을 끕니다(no_equals).
