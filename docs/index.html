SafeZsh for Claude

Claude writes bash; the Bash tool runs zsh. This plugin makes zsh read those commands like bash.

Without it, the command above stops with no matches found: --include=*.ts and grep never runs.

Install

At the Claude Code terminal prompt:

/plugin install safe-zsh --marketplace M1nu0x0/claude-safe-zsh

Answer y to Add marketplace? and choose the user scope.

From a shell:

claude plugin install safe-zsh --marketplace M1nu0x0/claude-safe-zsh

In Claude Desktop, click + next to the prompt box → Plugins → Add marketplace, enter M1nu0x0/claude-safe-zsh, then add safe-zsh. It applies from the next session.

Before and after

Why

On macOS the login shell is zsh, so the Bash tool runs commands in zsh, but Claude writes them for bash.

anthropics/claude-code#103027 counted 2,570 zsh errors in 61,040 Bash calls over twelve weeks. Since late September it was 51 per 1,000 calls, and 76% of them were silent: the command still exited 0, so the error sat in the middle of the output and Claude read on.

Once that issue is fixed in Claude Code, this plugin is no longer needed. CI checks the issue every day.

How it works

At session start (startup, resume, clear, compact) a SessionStart hook appends one line to CLAUDE_ENV_FILE. Claude Code prepends that file to every Bash tool command, so the line runs in the same shell.

if [ -n "${ZSH_VERSION:-}" ]; then setopt no_nomatch sh_word_split no_equals; fi

Under bash the condition is false and the line exits 0, so a command chained after it still runs.

What it fixes

no_nomatch
An unmatched glob such as --include=*.ts or ls libs/*/README.md is passed through instead of aborting the command.
sh_word_split
An unquoted $var splits into words, so for f in $list loops once per item.
no_equals
A word that starts with = stays as it is: echo ===== prints, and =ls is not turned into /bin/ls.

It does not fix colon modifiers ($B:path), $pat[...] read as a subscript, path and status as special variables, or bash-only syntax such as ${!v} and compgen. For those, CLAUDE_CODE_SHELL=/bin/bash runs the Bash tool in bash instead.

Questions

Does it change my terminal or ~/.zshrc?

No. The options apply only to the Bash tool's shell, not to your terminal, your dotfiles or a zsh -c started inside a command.

I use bash. Does it do anything?

No. Under bash the line's condition is false and it exits 0.

Why not just use CLAUDE_CODE_SHELL=/bin/bash?

That works and fixes more, but your zsh functions and settings are no longer available in the Bash tool. This plugin keeps zsh and turns off only the three behaviours that break most often.

Does it send data anywhere?

No. The hook only appends one line to a file Claude Code gives it.

Which systems is it tested on?

CI runs on Ubuntu and macOS, and every day against the latest Claude Code.

How do I remove it?

Run claude plugin uninstall safe-zsh in a shell.
