SafeZsh for Claude

Claude は bash で書き、Bash ツールは zsh で実行します。このプラグインは zsh にそのコマンドを bash と同じように読ませます。

このプラグインがないと、上のコマンドは no matches found: --include=*.ts で止まり、grep は実行されません。

インストール

Claude Code のターミナルのプロンプトで:

/plugin install safe-zsh --marketplace M1nu0x0/claude-safe-zsh

Add marketplace? に y と答え、scope は user を選びます。

シェルからは:

claude plugin install safe-zsh --marketplace M1nu0x0/claude-safe-zsh

Claude Desktop では、プロンプト横の + → Plugins → Add marketplace に M1nu0x0/claude-safe-zsh を入力し、safe-zsh を追加します。次のセッションから適用されます。

前と後

作った理由

macOS ではログインシェルが zsh なので Bash ツールも zsh でコマンドを実行しますが、Claude は bash の書き方でコマンドを書きます。

anthropics/claude-code#103027 は 12 週間で Bash の呼び出し 61,040 回のうち 2,570 回の zsh エラーを数えました。9 月下旬からは 1,000 回あたり 51 回で、その 76% はコマンドが 0 で終わったため、エラーが出力の途中に埋もれたまま Claude が読み進めていました。

この issue が Claude Code で修正されれば、このプラグインは不要になります。CI が毎日 issue の状態を確認しています。

動作

セッション開始時（startup、resume、clear、compact）に SessionStart フックが CLAUDE_ENV_FILE に 1 行を追記します。Claude Code はこのファイルを Bash ツールのコマンドごとに先頭に付けるので、その行が同じシェルで実行されます。

if [ -n "${ZSH_VERSION:-}" ]; then setopt no_nomatch sh_word_split no_equals; fi

bash では条件が偽になり 0 で終わるので、後に続くコマンドもそのまま実行されます。

防げるもの

no_nomatch
--include=*.ts や ls libs/*/README.md のように一致しない glob が、コマンドを止めずにそのまま渡されます。
sh_word_split
クォートしていない $var が単語に分割され、for f in $list が項目ごとに 1 回ずつ回ります。
no_equals
= で始まる単語をそのままにします。echo ===== が出力され、=ls が /bin/ls に変わりません。

コロン修飾子（$B:path）、添字として読まれる $pat[...]、特殊変数の path と status、${!v} や compgen のような bash 専用の書き方は防げません。その場合は CLAUDE_CODE_SHELL=/bin/bash で Bash ツールを bash で実行できます。

よくある質問

ターミナルや ~/.zshrc は変わりますか？

いいえ。オプションは Bash ツールのシェルにだけ適用されます。ターミナル、dotfile、コマンドの中で起動した zsh -c には適用されません。

bash を使っています。何かしますか？

いいえ。bash では条件が偽になり 0 で終わります。

CLAUDE_CODE_SHELL=/bin/bash を使えばよいのでは？

それでも動き、より多くの問題が解決しますが、Bash ツールで自分の zsh の関数や設定が使えなくなります。このプラグインは zsh のまま、最もよく壊れる 3 つだけをオフにします。

どこかにデータを送りますか？

送りません。フックは Claude Code から渡されたファイルに 1 行を追記するだけです。

どの OS で確認していますか？

Ubuntu と macOS で CI が動き、毎日最新の Claude Code でも確認しています。

削除するには？

シェルで claude plugin uninstall safe-zsh を実行します。
